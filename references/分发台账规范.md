# 分发台账规范（多平台发布）

> 来源：吸收 lornshrimp/Lorn.NovelWriteSkills《小说分发》目录方法论（2026-08-01）。
> 定位：写完正文之后的"分发端"收口。解决一稿硬拷 N 份、章节传错、重复上传、中断丢进度的问题。
> 原则：台账事实与后台事实必须一致；宁可慢，不可错传。

## 1. 目录路由（每平台一套）

```
{平台名}/README.md        # 平台分发配置（账号、书籍ID、卷名映射）
{平台名}/分发记录.md       # 章节唯一键 -> 平台章节Id 台账
{平台名}/正文/             # 该平台版本章节文件
```

- 主输出平台：章节文件可留在 `小说正文/`，配置和台账仍放 `{平台名}/`。
- 非主输出平台：全部独立成目录，正文版本与该平台强绑定。

## 2. 章节唯一键（强制）

格式：`书籍ID|分部名|卷号|章号|章名`

- 无分部时分部名填 `NA`
- 卷号、章号必须阿拉伯数字
- 用途：跨会话、跨平台判断"这章传没传过"，避免同卷同章号冲突

## 3. 分发记录.md 台账

```markdown
# {平台}分发记录
|章节唯一键|书籍ID|章节Id|最近操作|更新时间|备注|
```

- `章节Id`：平台发布页 URL 中 publish/ 后的数字
- 最近操作：`新建` 或 `修改`
- **每章即时回写，禁止批量后补**——中断时已传章节不丢映射

## 4. 新建/修改分流

- 台账无该章章节Id → 新建模式：`publish/?enter_from=newchapter`
- 台账已有章节Id → 修改模式：`publish/{章节Id}`
- 每章执行前必须重新查询台账，不得沿用上一章模式

## 5. 批量提效（5-10章一小批）

1. 预处理批量做：章节号/标题提取、平台字段拆分、字数预检、模式预判
2. 浏览器阶段固定节拍：开页 → 填标题 → 填正文 → 扩展字段 → 存草稿 → 取章节Id → 回写
3. 每批结束对账：`计划章数 = 成功 + 失败`，成功章必须完成章节Id回写
4. 失败分层：单章失败记录原因继续下一章；致命错误（书/卷不匹配、登录异常）立即停

## 6. 硬规则

- 章节标题从文件内容提取（通常第1行 `# `），不得用文件名
- 填正文前先校验页面左上角"书名+卷名"匹配，不匹配立即停
- 最终动作是"存草稿"不是"发布"，除非用户明确要求
- 账号密码仅用于当次登录，不写入产物文件
- 有话说（作者的话）先清空再录入，满足平台字数限制（常见300字）

## 7. 平台差异要点

- 番茄：分卷平台，章号用卷内相对章号，不做跨卷累加；作者有话说路径为"作者有话说→+添加→添加图文"
- 其余平台（起点/七猫/知乎/百家号/公众号/小红书等）：各自有分发 Skill，路径见 `ext-tools/Lorn.NovelWriteSkills/小说分发/`

## 8. 触发时机

写完一章/一批正文、作者要求发布或分发时启用。先建台账再动手。
